KETRIS: 7개 LLM 워크로드 전체 완료 시간 반복 실험

목표: 동일한 전체 작업을 MPS보다 빠르게 완료하거나 같은 시간에 더 많은 전체 작업을 완료하는지 확인.

공간 상한을 동일하게 맞춘 MPS 대비 완료 시간: 평균 1.1430% 더 김.

기본 NVIDIA MPS (상한 100%): 13.278790 ± 0.259817초; 범위 12.913953–13.623321초; 처리량 지수 100.0000%; GPU 가동률 80.1594%

KETRIS (상한 50% + phase75 크레딧): 13.576469 ± 0.107919초; 범위 13.399078–13.671604초; 처리량 지수 97.8074%; GPU 가동률 83.3205%

실험 구성:
10.0.1.211 VM, RTX PRO 6000 Blackwell Server Edition, driver 590.48.01, 188 SM, MIG Disabled.
VM CPU 8개, 메모리 약 32 GiB. 이미지 keti-exec/infer:0.2.
실험용 Pod 1개 안에서 Qwen2.5-0.5B-Instruct BF16 eager batch1 프로세스 7개 동시 시작.
W0–W2: 각 1024 입력 / 16 출력 토큰 × 8 요청.
W3–W6: 각 128 입력 / 128 출력 토큰 × 8 요청.
매 실행 합계 56 요청, 입력 28,672 토큰, 생성 4,480 토큰. 고정 길이 생성, EOS로 조기 종료하지 않음.
모델 준비 및 프로세스별 2회 워밍업 제외. 공통 시작 시각에서 7개 중 마지막 요청 완료까지 측정; 종료 구간 포함.
주 측정 3조건 × 5회 = 15회, 총 840 요청/67,200 생성 토큰. 별도 6회 사전 탐색은 평균에 미포함.
사전 탐색과 본 측정 모두 7개 동시 시작으로 고정. 본 측정 시작 전에 상한/정책을 고정하고 순서를 교대.

KETRIS 적용:
MPS 공간 상한 50%는 각 프로세스가 보고한 94 SM 상한. 전용 코어의 배타적 분할이 아님.
시간 크레딧은 프로세스별 경과시간 기반. 다른 워커가 decode 중일 때 prefill 크레딧을 75%로 공급.
decode/idle은 100%, 초기 크레딧 0, 적립 상한 500,000 us, 부채 유지. 500ms를 처음부터 지급한 것은 아님.
시간 크레딧 감소량이나 gate 횟수만으로 지속적인 단계별 실행 억제가 입증되는 것은 아님.

검증:
모든 21회 실행의 입력/출력 토큰 일치, 요청 수, 실행 시각, 바이너리/실행 소스, 종료 상태를 원본으로 검증.
크레딧 승인 횟수/전송량/부채 회계 검증 통과. 실험 중 관측된 외부 GPU 작업 없음.
노드 Ready, Memory/Disk/PID Pressure False. 운영 컨트롤러 32개, 큐 관련 객체 16개의 UID/spec 전후 동일.
전용 MPS와 실험 워커 종료. 기존 system MPS는 유지. GPU 드라이버/MIG 설정 변경 없음.

해석 범위:
GPU 가동률은 NVML sampled busy의 시간 가중 평균이며 전체 처리량 또는 유용 작업 효율과 다름.
가동률이 상승했어도 동일한 작업 완료 시간이 길어졌으므로 처리 성능이 개선되었다고 주장할 수 없음.
7개가 함께 시작하지만 W0–W2는 약 1.8–2.1초에 완료하며 이후 4개의 decode 중심 작업이 남음.
따라서 7개가 끝까지 지속적으로 포화된 서비스 테스트가 아니라, 정해진 작업 묶음의 완료 실험임.
Kubernetes 큐/승인/스케줄러 전체 E2E가 아닌 GPU 실행 경로 비교. NPU 및 MIG 내부 비교는 포함하지 않음.
5회 짧은 반복, 단일 장치/모델/작업 조합의 관측 결과이며 일반적인 성능 열세/우세로 확대하지 않음.
